# RK3588 (OrangePi 5 Plus)

## 硬件

- SoC: Rockchip RK3588 (aarch64, 8 核)
- 板卡: OrangePi 5 Plus
- 串口: `/dev/ttyS7`，波特率 1500000

## 构建命令

```bash
make build-rk3588       # 只编译内核 → output/rk3588/starryos.uimg
sudo make rk3588-sdcard # 编译内核 + 打包 SD 卡镜像 → output/rk3588/rk3588-sdcard.img
```

需要 `sudo` 因为脚本内部使用 `losetup` 创建 loop 设备。

## 前置准备：提取引导链

SD 卡镜像依赖 Rockchip 引导链（RKNS + SPL + ATF + U-Boot），需从 Armbian 官方镜像提取：

```bash
# 下载 Armbian 镜像（首次）
# https://github.com/orangepi-xunlong/orangepi-build/releases

# 提取前 16MB（扇区 0~32767）作为引导链
dd if=<armbian.img> of=output/rk3588/rk3588-bootchain.img bs=512 count=32768
```

Armbian 镜像分区布局（GPT）：

| 区域 | 扇区 | 内容 |
|------|------|------|
| 引导链 | 0 ~ 32767 | RKNS + SPL + ATF + U-Boot（16MB） |
| rootfs | 32768 起 | Linux root (ARM-64) |

## SD 卡镜像布局

`output/rk3588/rk3588-sdcard.img`（1GB）：

- 扇区 0~33: Protective MBR + GPT 头（由 `sfdisk` 写入）
- 扇区 34~32767: Rockchip 引导数据（SPL/ATF/U-Boot，从 bootchain dd 写入，跳过 GPT 头）
- 扇区 32768 起: ext4 rootfs（Alpine minirootfs aarch64 + `/starryos.uimg`）

## U-Boot 手动启动

写入 SD 卡后，在 U-Boot 命令行执行：

```bash
=> ext4load mmc 1:1 ${kernel_addr_r} /starryos.uimg
=> bootm ${kernel_addr_r} - ${fdtcontroladdr}
```

- `${kernel_addr_r}` = `0x02000000`（U-Boot 环境变量）
- `${fdtcontroladdr}` = U-Boot 内置 DTB 地址，通过 x0 传给内核
- 内核入口：`kernel_entry(_fdt_addr: usize)` 从 x0 读 DTB

## Board 配置

### 构建配置

`tgoskits/os/StarryOS/configs/board/orangepi-5-plus.toml`:

- `target = "aarch64-unknown-none-softfloat"`
- `env = { UIMAGE = "y" }`（启用 mkimage 打包 uImage）
- `plat_dyn = true`（动态平台发现）
- `max_cpu_num = 8`
- features: RK3588 PCIe/XHCI/SDHCI 驱动 + Realtek RTL8125 + RKNPU

### U-Boot 运行配置

`tgoskits/os/StarryOS/configs/board/orangepi-5-plus-uboot.toml`:

- `serial = "/dev/ttyS7"`
- `baud_rate = "1500000"`
- `kernel_load_addr = "0x02000000"`（与 U-Boot `kernel_addr_r` 一致）
- `fit_load_addr = "0x0a000000"`

## 注意事项

- Docker 容器 `starryos-act-infer` 同时用于 riscv64 和 aarch64 内核编译，内有 `/opt/aarch64-linux-musl-cross` 工具链
- Makefile 中 `find` 已限定架构子目录（`aarch64-unknown-linux-musl` / `riscv64-unknown-linux-musl`），避免多架构构建时找错 uImage
- Rockchip 引导链写入时跳过 GPT 头（扇区 0~33），`dd` 使用 `skip=34 seek=34`，避免覆盖 `sfdisk` 写入的分区表
