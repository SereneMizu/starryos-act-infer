# SG2002 TPU 推理部署

## 概览

在 SG2002 (CV181x) 开发板上运行 ACT 模型推理，利用板载 TPU 加速推理。

> **实际硬件**: 由于 LicheeRV-Nano 暂时不可用，使用同 SOC 的 **Milk-V Duo 256MB** 代替，StarryOS 运行良好。

整体流程：

```
ACT PyTorch 模型 → ONNX → TPU-MLIR BF16 cvimodel → StarryOS + TPU 推理程序
```

## 硬件与平台

- **开发板**: Milk-V Duo 256MB (SG2002, RISC-V 64bit)，与 LicheeRV-Nano 同 SOC
- **TPU**: Sophgo CV181x 内置 NPU，BF16 计算精度
- **内核**: StarryOS (tgoskits)，动态平台 (plat-dyn=true)
- **用户态**: Alpine musl rootfs，Rust 交叉编译推理程序

## 构建环境

需要两个 Docker 容器：

| 容器 | 镜像 | 用途 |
|------|------|------|
| `starryos-act-infer` | `ghcr.io/rcore-os/tgoskits-container:latest` | 内核编译、Rust 交叉编译（含 `/opt/riscv64-linux-musl-cross` 工具链）|
| `tpu-mlir-act` | `sophgo/tpuc_dev:latest` | TPU-MLIR 模型编译 (`model_transform.py` / `model_deploy.py`) |

## 构建命令

```bash
# 完整流程：编译内核 + TPU 模型编译 + 交叉编译推理程序 + 收集运行时库 + 打包 SD 卡镜像
sudo make sg2002-sdcard

# 只编译，不打包镜像
make build-sg2002

# 单独收集运行时动态库
make collect-sg2002-libs

# 启动/停止容器
make docker-up / make docker-down
make tpu-up    / make tpu-down
```

### 构建步骤详解

`make sg2002-sdcard` 执行以下步骤：

1. **启动容器** — 启动 `starryos-act-infer` 和 `tpu-mlir-act` 两个 Docker 容器
2. **编译 StarryOS 内核** — 使用 tgoskits xtask 编译 `licheerv-nano-sg2002.toml` 板级配置，输出 `starryos.uimg`
3. **收集运行时动态库** — `scripts/collect-sg2002-libs.sh` 从各来源收集 `.so` 到 `starry-apps/act-infer-tpu/lib/`
4. **TPU 模型编译** — `scripts/tpu_compile.py` 将 ONNX 转为 BF16 cvimodel（~96MB）
5. **交叉编译推理程序** — `act-infer-tpu` 静态链接 Rust 代码，动态链接 CVI 运行时库
6. **打包 SD 卡镜像** — `scripts/build-sg2002-sdcard.sh` 生成 1GB 镜像

## 运行时动态库收集

运行时库从两个来源动态收集（不随仓库提交）：

| 库 | 来源 | 用途 |
|----|------|------|
| `libcviruntime.so` | official.img (`usr/bin/lib/`) | CVIRuntime，CVI_NN_* API |
| `libcvikernel.so` | official.img (`usr/bin/lib/`) | CVI kernel 层 |
| `libcvimath.so` | official.img (`usr/bin/lib/`) | CVI 数学运算 |
| `libstdc++.so.6` | tgoskits 容器 (`/opt/riscv64-linux-musl-cross/riscv64-linux-musl/lib/`) | C++ 运行时 |
| `libgcc_s.so.1` | tgoskits 容器 (`/opt/riscv64-linux-musl-cross/riscv64-linux-musl/lib/`) | GCC 运行时 |

收集脚本 `scripts/collect-sg2002-libs.sh`：
- CVI 库：挂载 `output/sg2002/official.img` 的 p2 分区，从 `usr/bin/lib/` 拷贝
- GCC/C++ 库：从 `starryos-act-infer` 容器的 musl 工具链目录拷贝

Staging 目录：`starry-apps/act-infer-tpu/lib/`（已 gitignore，仅保留 `.gitkeep`）

## TPU 模型编译

```bash
# 在 tpu-mlir-act 容器内执行
python scripts/tpu_compile.py --quantize BF16 --processor cv181x
```

- 输入：ONNX 模型 (`output/train/model.onnx`)
- 输出：`output/tpu/act_model_cv181x_bf16.cvimodel`（~96MB）
- 量化：BF16（输入 FP32，内部 BF16 计算，输出 FP32）
- 处理器：cv181x

## 内核板级配置

`tgoskits/os/StarryOS/configs/board/licheerv-nano-sg2002.toml`：

```toml
env = { UIMAGE = "y" }
features = [
  "starry-kernel/sg2002",      # TPU 驱动 + ION + DMA + 串口
  "axplat-dyn/thead-mae",       # 动态平台，T-HEAD MAE
  "ax-driver/sg2002-placeholder",
  "ax-driver/cvsd",
  "ax-driver/serial",
]
log = "Info"
plat_dyn = true                 # 动态平台（静态平台会 NULL 函数指针崩溃）
target = "riscv64gc-unknown-none-elf"
```

### tgoskits 本地 patch

上游 TPU/ION 设备注册在 `#[cfg(all(feature = "sg2002", not(feature = "plat-dyn")))]` 条件下，但静态平台 (`plat_dyn=false`) 在 SG2002 上启动会 Instruction access fault。我们使用动态平台 (`plat_dyn=true`)，并放开 TPU/ION 相关的 cfg gate。

涉及文件（`tgoskits/os/StarryOS/kernel/src/`）：

- `file/mod.rs` — ion 模块注册
- `pseudofs/dev/mod.rs` — ion/tpu 模块注册、ION_DEVICE 静态量、cvi-tpu0/ion 设备节点创建
- `syscall/mm/mmap.rs` — IonBufferFile mmap 特殊处理

改为 `#[cfg(feature = "sg2002")]`，去掉 `not(feature = "plat-dyn")` 条件。

**注意**：pwm、ttyS1/ttyS2、camera、pinmux 等非 TPU 设备仍保留 `not(plat-dyn)` 条件。

## 推理程序

`act-infer-tpu/` — Rust 编写的 TPU 推理程序：

- **链接方式**：动态链接 `libcviruntime.so`、`libcvikernel.so`、`libcvimath.so`、`libstdc++.so.6`、`libgcc_s.so.1`
- **交叉编译目标**：`riscv64gc-unknown-linux-musl`
- **FFI 绑定**：`bindings.rs` 手动裁剪的 CVIRuntime FFI 绑定，直接调用 `CVI_NN_*`
- **推理流程**：图像预处理 (resize 224x224 + ImageNet 归一化) → 写入 TPU 输入 tensor → `CVI_NN_Forward` → 读输出 tensor (BF16→FP32) → 反归一化

### 命令行参数

```
act-infer-tpu --model <cvimodel> --dir <frames_dir> --stats <stats.json> [--reference <ref.json>] [--track-mem]
```

### 时间统计

每帧计时从图像加载开始（预处理 + tensor 拷贝 + TPU 推理），单位 ms。

### 内存追踪

`--track-mem` 启用进程级峰值内存追踪，轮询 `/proc/self/status` 的 VmSize 取最大值。

## SD 卡镜像

`output/sg2002/sg2002-sdcard.img`（1GB）：

| 分区 | 大小 | 内容 |
|------|------|------|
| p1 (boot) | 16MB | 官方 u-boot（从 official.img dd 写入）|
| p2 (rootfs) | ~984MB | ext4，Alpine musl rootfs |

Rootfs 内容：

```
/
├── starryos.uimg                    # StarryOS 内核镜像
├── lib/
│   ├── libcviruntime.so             # CVI 运行时
│   ├── libcvikernel.so              # CVI kernel
│   ├── libcvimath.so                # CVI 数学
│   ├── libstdc++.so.6               # C++ 运行时
│   ├── libstdc++.so -> libstdc++.so.6
│   ├── libgcc_s.so.1                # GCC 运行时
│   └── libgcc_s.so -> libgcc_s.so.1
├── usr/bin/
│   └── act-infer-tpu                # 推理程序
└── opt/act-infer/
    ├── model.cvimodel               # TPU 模型（~96MB）
    ├── frames/                      # 测试图片
    ├── stats.json                   # 归一化参数
    ├── reference.json               # ONNX 参考结果（可选）
    └── infer.sh                     # 推理启动脚本
```

## 启动

在 U-Boot 命令行执行：

```
ext4load mmc 0:2 0x80200000 /starryos.uimg; bootm 0x80200000 - $fdtcontroladdr;
```

系统启动后运行推理：

```bash
/opt/act-infer/infer.sh
```

## 写入 SD 卡

```bash
sudo dd if=output/sg2002/sg2002-sdcard.img of=/dev/sdX bs=4M status=progress && sync
```

将 `/dev/sdX` 替换为实际的 SD 卡设备。

## 运行结果

### 性能概要

| 指标 | 值 |
|------|-----|
| 总帧数 | 666 |
| 总耗时 | 301.40s |
| 平均帧耗时 | 452.6ms |
| 最小帧耗时 | 389ms |
| 最大帧耗时 | 719ms |
| 峰值内存 (VmSize) | 114 MB |

### 精度验证（对比 ONNX CPU 推理参考值）

| 指标 | 值 |
|------|-----|
| 转向匹配率 | 631/666 (94.7%) |
| 转向不一致 | 35/666 |
| 最大 left_vel 偏差 | 0.001925 |
| 最大 right_vel 偏差 | 0.001498 |

35 帧不一致全部是左右轮速度差极小的边界翻转（差值 < 0.01），BF16 量化精度损失可接受，不影响实际控制决策。
